# NOVA 0.14 — усиление защиты

Дата проверки: 16 октября 2026 года. Проверены исходный код этого репозитория,
установленные npm-зависимости и локальные сценарии API/браузера. Это не внешний
пентест, не сертификация OWASP и не аудит действующего VDS. Гарантии отсутствия
всех уязвимостей нет.

## Что найдено и изменено

| Находка | Изменение |
| --- | --- |
| В `file-type` 20.x есть опубликованные проблемы доступности: чрезмерная распаковка ZIP и зацикливание ASF-парсера. Старый код определял тип любого загруженного файла этим парсером. | Зависимость удалена. До декодирования проверяются только сигнатуры JPEG/PNG/WebP; затем изображение декодируется и пересохраняется через `sharp`. Путь загрузки и раньше требовал входа — анонимная эксплуатация этого обработчика не была установлена. |
| Счётчик попыток входа находился только в памяти процесса. | Атомарный счётчик в PostgreSQL (`auth_throttle`), 10 попыток на IP за 15 минут, очистка по сроку и после успешного входа. Перезапуск API не обнуляет блокировку. |
| Проверки паролей и обработка изображений могли создавать неограниченную очередь тяжёлых задач. | Отдельные лимиты по 2 одновременные операции; переполнение возвращает 503 без очереди. Добавлены общие лимиты запросов, тайм-ауты HTTP/SQL и пула БД. |
| В Vite-командах разработки был указан `0.0.0.0`. | Разработка и preview по умолчанию доступны только через loopback; имя/порт закреплены. Сервер разработки не предназначен для размещения в интернете. |
| Не было общих браузерных политик защиты для HTML и ошибок API. | CSP, запрет фреймов, `nosniff`, Referrer/Permissions Policy, same-origin CORP. API не кэшируется; HTTPS-профиль добавляет HSTS. Для готового HTML заголовки должен отдавать веб-сервер — приложен шаблон Nginx. |
| Некоторые ошибки библиотек могли возвращать внутренний текст клиенту. | Обобщённые ответы, редактирование чувствительных полей журналов, исключение query string из журнала запросов. SQL и тела запросов не возвращаются в ошибке. |
| Старые/импортированные данные могли обойти новую проверку ссылок при отображении меню. | Общая проверка безопасных ссылок на сервере и в интерфейсе. Текст продолжает выводиться с экранированием HTML, без `v-html`. |
| Перед публикацией можно было оставить секреты и привилегированную роль БД из разработки. | Production-профиль отказывается стартовать с известными шаблонными настройками, без HTTPS-origin админки и с ролью БД, имеющей проверяемые привилегии суперпользователя/управления ролями/доступа к серверным файлам и программам. |

## Дополнительные барьеры

- Вход и CSRF проверяются до разбора тела запроса у защищённых маршрутов.
- Общий предел JSON — 2 МиБ; загружается ровно один файл до 5 МиБ.
- Новые изображения: не более 20 млн пикселей, 10 000 px на сторону; анимация
  отклоняется; результат WebP до 4096 px на сторону и 5 МиБ, без EXIF и комментариев.
  Старые файлы автоматически не перекодируются.
- Выдача файлов идёт потоком, без загрузки целого файла в память; симлинки,
  каталоги и файлы больше лимита не выдаются.
- Сессия: 8 часов максимум, 30 минут без запросов к API. Долгое редактирование
  без сохранения/других запросов не продлевает сессию.
- «Выйти везде» отзывает все сессии. Смена пароля также завершает все сессии.
- HTTPS-cookie использует префикс `__Host-`, Secure, HttpOnly, SameSite=Strict,
  Path=/ и не имеет Domain. После обновления production-профиля может потребоваться
  повторный вход. Локальная cookie не меняет имя.
- API: 240 запросов/IP/минуту и 2400 на процесс/минуту, ограниченная память счётчика.
  Эти общие лимиты сбрасываются при рестарте; счётчик попыток входа — нет.
- PostgreSQL: до 10 соединений, ожидание соединения до 5 секунд, statement_timeout
  5 секунд, lock_timeout 3 секунды, idle-in-transaction timeout 15 секунд.
- Запросы к БД используют параметры. Закрытые страницы/статьи/товары проверены
  на недоступность без сессии. Старый X-Admin-Key не даёт административного доступа.
- Медиатека требует входа; сами изображения сайта остаются публичными по URL.
  Это не хранилище конфиденциальных документов.

## Проверки

- `npm ci`, обе production-сборки и `npm test`.
- 22 автоматических теста: auth/CSRF, отзыв и истечение сессий, счётчик попыток
  после нового экземпляра API, загрузки, лимиты, безопасные ссылки, ошибки,
  конфигурация production и существующая медиатека/блог/страницы.
- `npm audit`: 0 известных уязвимостей npm в установленном дереве на момент проверки.
  Это не проверка всех нативных компонентов и не гарантия будущего состояния.
- Полный сервер с PGlite: недоступность черновиков, запрет старого ключа API,
  CSRF, prototype pollution, подмена MIME, большие тела, обход путей файлов,
  подмена X-Forwarded-For и сохранённый счётчик попыток.
- Chromium с готовыми сборками и настоящим API/PGlite: вход, восстановление
  сессии, загрузка и пересохранение фото, выход везде; HTML отображается текстом,
  опасные ссылки скрыты, inline-script блокируется CSP.
- Для GitHub Actions добавлены установка из lock-файла, аудит, тесты и сборки.
  Действия закреплены commit SHA, workflow не имеет прав записи и не использует
  production-секреты. Его запуск на GitHub проверяется отдельно после push.

## Размещение

1. Не публикуйте Vite dev/preview. Соберите `npm run build` и отдавайте только
   `apps/storefront/dist` и `apps/admin/dist`. Админку лучше вынести на отдельный
   домен. Пример: `deploy/nginx.conf.example` и два include-файла рядом.
2. Используйте поддерживаемый Node.js 22.12+ с актуальными исправлениями,
   HTTPS, `NODE_ENV=production`, `SESSION_SECURE=true` и точный
   `ADMIN_ORIGINS=https://admin.example.com` без завершающего `/`.
3. Замените `ADMIN_API_KEY` случайным секретом от 32 символов. Текущий пароль
   администратора остаётся в БД; этот ключ не заменяет пароль и не даёт входа.
4. Нужна отдельная PostgreSQL-роль без SUPERUSER, CREATEDB, CREATEROLE,
   REPLICATION, BYPASSRLS и членства в привилегированных серверных ролях.
   Текущая версия выполняет миграции при старте и требует владения объектами
   схемы NOVA; отдельный пользователь миграций пока не выделен. Настройку прав
   существующего кластера выполняйте отдельно: не понижайте единственного
   суперпользователя без сохранённого административного доступа.
5. Слушайте API на 127.0.0.1 и не открывайте PostgreSQL наружу. `TRUST_PROXY`
   оставляйте пустым без прокси; `loopback` допустим только для локального Nginx,
   который перезаписывает X-Forwarded-For. Нельзя доверять заголовкам от любых IP.
6. Nginx-шаблон требует замены доменов, путей и сертификатов, проверки `nginx -t`
   и настройки firewall. В этой среде шаблон не установлен на действующий VDS.
   Заголовки HTML не появляются на произвольном хостинге только от копирования dist.
7. Сервис должен работать отдельным непривилегированным пользователем ОС,
   с закрытым `.env` и записью только туда, где это нужно. Папку uploads можно
   вынести через UPLOAD_DIRECTORY; перенос файлов выполняется отдельно.
8. Резервируйте PostgreSQL и uploads, храните копию отдельно и проверяйте
   восстановление. Защита хоста, TLS, резервные копии и сетевой DDoS-сервис
   в этом изменении автоматически не настраиваются.

Дополнительно полезны второй фактор входа и отдельные роли редакторов — сейчас
их нет. Компрометация компьютера администратора, пароля или самого сервера
не устраняется одними проверками в коде CMS.

## 0.15: редактор оформления

Изменения оформления проходят существующую сессионную авторизацию, CSRF и проверку Origin. Черновики/история недоступны публичному API; публикация использует блокировку строки и ожидаемый номер ревизии. Код и настройки ограничены размером, известной схемой и типами.

HTML/JS кода не вставляются в DOM админки или обычной страницы магазина. Рендерер `/api/code-frame` имеет отдельный nonce CSP, `sandbox allow-scripts` без `allow-same-origin`, ограниченные источники изображений, запрет fetch/XHR, форм, вложенных фреймов и объектов. Сообщения фильтруются по source/origin/идентификатору блока; в блок передаются только публичные данные. Предпросмотр не обрабатывает команды перехода родительского окна. В опубликованном блоке разрешены переходы к внутренним публичным страницам. Клиентский JS не исполняется Node.js и не получает файловый доступ.

Sandbox изолирует полномочия, но не гарантирует защиту браузера от зависания намеренно тяжёлого JS; предпросмотр запускается вручную. Пользовательский код — доверенное действие администратора: не вставляйте в него секреты. Публичные изображения имеют CORP cross-origin, чтобы загружаться внутри opaque iframe; административные JSON-ответы сохраняют CORP same-origin. Nginx обязан сохранить CSP самого рендерера через отдельный location из примера.

`NOVA.request` — отдельный мост публичного чтения: строгий список URL, GET, credentials omit, лимиты по количеству/параллельности и времени. Он не принимает методы, заголовки или тело от пользовательского кода. Предпросмотр не выполняет такие запросы. Это позволяет полной теме читать опубликованные страницы/статьи/каталог, сохраняя изоляцию административной сессии.
