# Темы и шаблоны NOVA CMS

Руководство для NOVA Engine **0.20+**, формат пакетов и API темы — **1**.

Темы пишутся на **HTML, CSS и JavaScript**, устанавливаются через админку без пересборки CMS. Серверные плагины, PHP, npm-зависимости и исполняемые установщики не поддерживаются. Код темы выполняется в изолированном iframe. Данные, заказы, контакты и секреты принадлежат CMS.

- **Тема (`nova-theme`)** задаёт цвета, размеры, внешний CSS, параметры владельца и шаблоны вывода.
- **Шаблон страницы (`nova-template`)** — заготовка заголовка, вступительного текста и секций для редактора страниц. После применения это обычная редактируемая страница, независимая от исходного пакета.

## 1. Быстрый старт

Клонируйте репозиторий, установите зависимости и запустите CMS по [README](../README.md). Нужны Node.js 22.12+ и PostgreSQL; локальная база запускается через Docker Compose.

Из корня репозитория:

```bash
npm ci
npm run theme:pack -- examples/themes/nova-studio my-theme.nova.json
npm run theme:check -- my-theme.nova.json
```

В PowerShell команды те же; запускайте их из `D:\Idea\nova-engine` или своего каталога проекта. Пути с пробелами заключайте в кавычки.

Откройте **Темы и шаблоны → Выбрать .nova.json**. Изучите название, версию, код исходников и состав. При необходимости явно выполните предпросмотр. Нажмите **Установить / обновить пакет**. Сайт при этом не изменяется.

В библиотеке нажмите **Применить к черновику**, затем откройте **Оформление и код → Тема и шаблоны**. Выберите локальную форму, изображения и значения параметров. Сохраните и нажмите **Опубликовать**. Обновите витрину. Встроенные примеры можно открыть прямо из библиотеки без загрузки файла.

Готовые примеры:

- [Исходники NOVA Studio](../examples/themes/nova-studio/) и [готовый пакет темы](../examples/themes/nova-studio/theme.nova.json).
- [Исходники страницы контактов](../examples/templates/contact-page/) и [готовый пакет страницы](../examples/templates/contact-page/template.nova.json).

## 2. Структура исходников темы

```text
my-theme/
  manifest.json
  design.json
  site.css
  base.css
  templates/
    home/
      index.html
      style.css
      script.js
    catalog/
      index.html
      style.css
      script.js
    product/
      index.html
      style.css
      script.js
```

`manifest.json` и `design.json` обязательны. `site.css`, `base.css`, отдельные шаблоны и их файлы необязательны. Сборщик добавляет `base.css` перед `style.css` каждого существующего шаблона. Если все три файла места пусты/отсутствуют, оно использует стандартный вывод CMS.

Сборщик читает только фиксированные имена файлов. Он не запускает код темы, не выполняет команды из manifest, не скачивает зависимости и не упаковывает другие файлы. Символические ссылки на файлы и выход из каталога запрещены. ZIP-архивы не импортируются: результат сборки — один JSON.

### manifest.json

```json
{
  "format": "nova-theme",
  "apiVersion": 1,
  "manifest": {
    "id": "my-theme",
    "name": "Моя тема",
    "version": "1.0.0",
    "description": "Краткое описание",
    "author": "Автор темы",
    "license": "MIT"
  },
  "settings_schema": [
    {"id":"headline","label":"Заголовок","type":"text","default":"Добро пожаловать"},
    {"id":"contact-form","label":"Форма связи","type":"form","default":""}
  ]
}
```

ID: до 80 символов, строчные латинские буквы, цифры и дефисы; первый символ — буква. Версия: `major.minor.patch`, допускается суффикс вроде `1.0.0-beta.1`. Все поля manifest из примера обязательны; description, author и license могут быть пустыми строками. Укажите реальную лицензию своей работы; надпись в manifest не предоставляет прав на чужие изображения или код.

### design.json

```json
{
  "colors": {
    "primary":"#264e46", "accent":"#c07542", "background":"#fbfaf6",
    "text":"#18322c", "hero":"#eeeee4", "footer":"#18322c"
  },
  "font":"Arial",
  "radius":14,
  "width":1220,
  "visibility":{"announcement":false},
  "home_order":["hero","advantages","catalog"]
}
```

Все поля стиля необязательны. Неуказанные значения при применении берутся из стандартной темы, а не предыдущей. Допустимые шрифты: `Manrope`, `Arial`, `Georgia`, `Verdana`; ширина 900–1600 px, радиус 0–32 px. Цвета — `#RRGGBB`.

Ключи visibility: `announcement`, `header`, `hero`, `advantages`, `catalog`, `footer`, `year`, `floating`. home_order — перестановка трёх значений из примера. hero/advantages/catalog управляют стандартными секциями: собственный HTML обязан сам учитывать нужную структуру. Общая видимость шапки/подвала применяется до запуска их шаблонов.

`site.css` влияет на **внешний документ витрины**, включая стандартные секции и интерфейс корзины. Не используйте его для админки. Этот CSS сохраняется в `code.global_css`. CSS шаблона действует только внутри его iframe; правила из site.css туда не переходят.

## 3. Места шаблонов

| Каталог / ключ | Когда используется | Дополнительный контекст |
|---|---|---|
| `header` | Шапка, если включена | Общие данные |
| `home` | `/` | `context.page`, если главной назначена CMS-страница |
| `catalog` | Каталог; также стандартная главная без home-шаблона | `products` |
| `product` | Существующая карточка товара | `context.product` |
| `page` | Вступительная часть CMS-страницы | `context.page` |
| `blog` | Список статей после стандартных заголовка/фильтров | `context.blog` |
| `post` | Содержимое статьи | `context.post` |
| `footer` | Подвал, если включён | Общие данные |

Для главной CMS-страницы используется home, если он задан, иначе page. **Секции CMS-страницы всегда выводятся после её шаблона**, поэтому размещённые через редактор формы продолжают работать. Не дублируйте вывод sections в своём вступительном шаблоне. Фильтры и пагинация блога также остаются в CMS.

При отсутствии шаблона используется стандартный вывод. При ошибке/необработанном Promise в JS шаблона CMS переключает соответствующий блок на стандартный вывод. Ошибки разметки или неверный макет сами по себе не определяются. Бесконечный цикл способен зависнуть в браузере — проверяйте код локально.

Старый собственный блок `code.placement=home/site` имеет приоритет над шаблонами соответствующего содержимого. Применение нового пакета выключает старый блок в черновике; его исходники остаются в оформлении и истории.

## 4. HTML, CSS и JavaScript

HTML вставляется как содержимое отдельного документа. В `index.html` пишите разметку, а поведение — в `script.js`. Теги `<script>`, inline-обработчики `onclick`, `javascript:` и динамический `eval` не являются способом запуска скриптов темы. Внешние JS/CSS-библиотеки и вложенные iframe заблокированы CSP.

Минимальный пример:

```html
<section class="welcome">
  <h1 id="title"></h1>
  <button id="cart">Корзина</button>
  <p id="status" role="status"></p>
</section>
```

```css
.welcome { padding: 32px; background: var(--nova-hero); }
h1 { color: var(--nova-primary); }
button { border-radius: var(--nova-radius); }
```

```js
function render() {
  document.getElementById('title').textContent = NOVA.settings.name;
}
document.getElementById('cart').addEventListener('click', async () => {
  try { await NOVA.cart.open(); }
  catch (e) { document.getElementById('status').textContent = e.message; }
});
render();
addEventListener('nova:context', render);
```

`script.js` — обычный скрипт, не ES-модуль. Для await при старте используйте async-функцию с catch. Встроенный предпросмотр не даёт доступа к API/действиям; он предназначен для макета. На витрине `nova:context` сообщает об изменении публичного контекста (например, загрузке каталога или изменении корзины). Добавляйте обработчики DOM один раз и обновляйте только необходимые элементы.

Перед JS в документ устанавливаются CSS-переменные `--nova-primary`, `--nova-accent`, `--nova-background`, `--nova-text`, `--nova-hero`, `--nova-footer`, `--nova-radius`, `--nova-width`. `--nova-width` — целевая максимальная ширина, а не фиксированная ширина мобильного экрана. Стройте адаптивный макет с max-width, grid и media queries. Цвета/фон самого body задаёт автор.

Логотипы и фотографии берите из публичных данных CMS, например `NOVA.settings.logo_url` и `product.image_url`. Маленькие иллюстрации можно рисовать CSS или встроенной SVG-разметкой. В формате v1 нет автоматического импорта бинарных изображений/шрифтов: загрузите изображения в медиатеку и выберите в настройках темы. Не переносите URL `/uploads/<uuid>` с другого сайта.

## 5. Данные `window.NOVA`

| Поле | Содержимое |
|---|---|
| `apiVersion` | `1` |
| `settings` | Публичные настройки: имя, логотип, меню, статусы магазина/блога |
| `products` | Загруженные опубликованные товары; список может быть пуст при старте |
| `design` | texts, colors, font, width, radius; без исходников других шаблонов |
| `theme` | id, version и `settings` активной темы |
| `route` | path и строка разрешённых параметров блога без `?`; на других маршрутах search пуст |
| `context` | Данные конкретного места из таблицы выше |
| `cartSummary` | count и total_cents; без контактов, квитанций и данных заказов |

Типичные поля товара: `id` (число), `name`, `category`, `description`, `price` (рубли), `stock`, `image_url`, `images`, `attributes`, `variants`. У варианта: name, sku, price, stock. Эти данные помогают отрисовке, но не являются доказательством наличия или окончательной суммы: сервер заново проверяет их при оформлении заказа.

На странице `context.page` содержит заголовок, текст и публичные секции; на статье `context.post` — публичную запись блога. У списка `context.blog` есть items, total, categories и tags. Для точных полей смотрите [API страниц](../apps/api/src/pages.js), [блога](../apps/api/src/blog.js) и [витрины](../apps/api/src/server.js).

### Безопасный вывод

Предпочитайте `element.textContent` для названий и текстов CMS. Для HTML-строк доступна `NOVA.escape(value)` — экранирование текста/значения атрибута, **не** проверка URL или JavaScript. Не вставляйте в HTML неэкранированный контент. `NOVA.money(cents)` форматирует копейки как рубли:

```js
price.textContent = NOVA.money(Math.round(product.price * 100));
```

## 6. Чтение публичного API

На опубликованной витрине:

```js
async function loadPosts() {
  try {
    const blog = await NOVA.request('/api/blog?page=1');
    // Заполняйте DOM через textContent.
  } catch (e) { status.textContent = e.message; }
}
loadPosts();
```

Разрешены только GET публичных маршрутов: `/api/products`, `/api/products/<id>`, `/api/categories`, `/api/pages`, `/api/pages/<slug>`, `/api/blog`, `/api/blog/<slug>`. Сервер сам проверяет публикацию и статус модулей. Мост не пересылает cookie; административные маршруты, настройки доставки, заказы, платежи и POST недоступны. До 100 запросов/действий на экземпляр iframe, до 3 одновременных; ответ до 2 МБ, ожидание до 10 секунд. Fetch/XHR из самой темы заблокирован.

## 7. Корзина и формы

Действия разрешены только на опубликованной витрине после реального нажатия пользователя. Вызывайте их непосредственно в click/клавиатурном обработчике до длительных await. Не пытайтесь выполнить действие при загрузке, из таймера или при предпросмотре.

```js
await NOVA.cart.add(product.id);                         // обычный товар
await NOVA.cart.add(product.id, variant.name, 2);        // выбранный вариант
await NOVA.cart.open();                                 // штатная корзина
await NOVA.forms.open(NOVA.theme.settings['contact-form']);
```

Все методы возвращают Promise. `cart.add` принимает числовой ID, точное имя варианта и целое количество 1–100, возвращает summary. Для вариативного товара надо явно выбрать вариант. CMS проверяет товар в своём публичном каталоге, остаток и блокировку оформления; клиентские цены и произвольные дополнительные поля не принимаются.

Метод `forms.open` открывает **штатную форму CMS** поверх страницы. Он не отправляет данные автоматически и не раскрывает SMTP-пароль, Telegram token, получателей или обращения. Выберите form-параметр темы в админке. У формы должны быть включены приём и каналы; её поля/согласие/доставка управляются разделом «Формы и заявки».

Оформление заказа, контакты, платёжный ключ и передача обращения остаются за пределами темы. Не пишите сбор банковских данных или SMTP/Bot API в шаблоне. Для оплаты используйте штатный раздел CMS. Скрипты платёжного виджета не вставляются в тему: для них предусмотрена отдельная изоляция.

Обычные внутренние ссылки `<a href="/catalog">` и `/product/<id>` открываются в родительской витрине. Внешняя навигация, административные пути и переходы к API блокируются. Якорь `#...` работает внутри самого iframe. Не используйте `window.parent`, top.location или location.href вместо обычной ссылки.

## 8. Настройки владельца темы

settings_schema содержит до 20 полей; id уникален и имеет тот же формат, что ID пакета.

| type | default / значение | Управление в админке |
|---|---|---|
| text | Строка до 3000 символов | Текстовое поле |
| color | `#RRGGBB` | Выбор цвета |
| checkbox | true / false | Флажок |
| select | Строка из options | Список |
| form | Пустая строка в пакете, затем UUID местной формы | Выбор формы |
| image | Пустая строка в пакете, затем URL местной медиатеки | Медиатека |

Для select задайте options, например:

```json
{"id":"density","label":"Плотность","type":"select","default":"normal","options":[{"value":"normal","label":"Обычная"},{"value":"compact","label":"Компактная"}]}
```

Настройки доступны в `NOVA.theme.settings['density']`. При применении пакета они устанавливаются в defaults. Условия и обработку параметров реализует автор JS/CSS. Наименования настроек и интерфейс выбора не меняют бизнес-логику CMS.

## 9. Шаблоны страниц

Каталог шаблона содержит `manifest.json` и `page.json`:

```json
{
  "format":"nova-template", "apiVersion":1,
  "manifest":{"id":"about-page","name":"О компании","version":"1.0.0","description":"Заготовка страницы","author":"Автор","license":"MIT"}
}
```

```json
{
  "title":"О компании",
  "content":"Вступительный текст",
  "sections":[
    {"id":"intro","type":"text","title":"Наш подход","text":"Замените этот текст","image_url":"","alt":"","caption":"","button_text":"","button_url":""}
  ]
}
```

Поддержаны штатные секции hero, text, image, code, form; ограничения соответствуют [валидатору секций](../shared/pageSections.js). Для hero/text/image укажите все строковые поля, как в примере. У code — объект code с html/css/js, у form — form_id. Для переносимого пакета image_url и form_id пустые. После применения выберите местные ресурсы; форму с пустым form_id нельзя сохранить до выбора или удаления секции.

```bash
npm run theme:pack -- examples/templates/contact-page my-page.nova.json
npm run theme:check -- my-page.nova.json
```

Установите JSON в библиотеку. Откройте редактор новой/существующей страницы, выберите **Шаблон страницы → Заполнить шаблоном**, отредактируйте секции и сохраните. Шаблон не назначает slug, главную страницу, публикацию, SMTP, оплату и другие настройки сайта. ID секций при заполнении создаются заново.

## 10. Формат готового JSON

Сборщик создаёт один из двух документов:

```js
// Тема
{
  format: 'nova-theme', apiVersion: 1, manifest: { /* метаданные */ },
  style: { /* design.json, а также site_css из site.css */ },
  settings_schema: [ /* настройки */ ],
  templates: { home: { html: '...', css: '...', js: '...' } }
}
// Шаблон страницы
{
  format: 'nova-template', apiVersion: 1, manifest: { /* метаданные */ },
  page: { title: '...', content: '...', sections: [ /* секции */ ] }
}
```

Неизвестные поля верхнего уровня и произвольные места шаблонов отклоняются. Ограничения v1:

- Пакет — до **512 КиБ UTF-8**, библиотека — до 50 пакетов.
- HTML/CSS/JS каждого места — до 50 000 символов на файл, суммарно до 350 000.
- site_css — до 100 000 символов, полное оформление с темой — до 1 МиБ UTF-8.
- Шаблон страницы — до 50 секций; код секции имеет собственные ограничения штатного редактора.

Это ограничения принятого JSON, а не размер исходного каталога. Отформатированный файл с отступами тоже должен укладываться в 512 КиБ при загрузке. Слишком большой готовый файл уменьшите или сохраните компактным JSON.

## 11. Обновление, экспорт и откат

Пара kind/id уникальна. Импорт того же ID обновляет пакет с проверкой revision, но **не** меняет применённый черновик или опубликованный сайт. Для обновления сайта примените новую версию и снова опубликуйте. Версия manifest помогает учёту; правило «только повышение версии» не навязывается. Смена API требует другого поддерживаемого apiVersion, несовместимые пакеты не установятся.

Применение сохраняет состояние «До применения темы» в последних 30 версиях оформления. Оно оставляет тексты, выбранные изображения главной, товары, страницы, статьи, меню и сервисы сайта, но заменяет параметры стиля, внешний CSS и активные шаблоны. Проверка revision предотвращает перезапись изменившегося черновика. Публикация — отдельное действие.

Откат: **Оформление и код → История → Восстановить в редактор → Сохранить / Опубликовать**. Для отдельного места выберите «Использовать стандартный шаблон здесь». Удаление активных шаблонов не сбрасывает цвета и site.css; их можно изменить отдельно или восстановить полную версию.

**Экспорт темы черновика** включает текущие метаданные, шаблоны, стиль и настройки как defaults. Локальные form/image bindings сбрасываются в пустые значения для переносимости. Бизнес-данные и секреты в пакет не экспортируются. Загруженный для просмотра пакет можно скачать без применения.

## 12. Проверка перед выпуском

1. Выполните theme:check и проверьте пакет в локальной CMS.
2. Проверьте пустой каталог, отключённый магазин/блог, отсутствие фото и длинные названия.
3. Проверьте ширину 375 px и клавиатурную навигацию; у кнопок должны быть понятные названия.
4. Проверьте варианты/нулевой остаток, корзину, штатное оформление и обратную связь с тестовыми каналами.
5. Убедитесь, что JS корректно обрабатывает ошибки Promise и обновление nova:context.
6. Проверьте отсутствие реквизитов, ключей, адресатов, локальных UUID и чужих изображений в исходниках.
7. Укажите версию, автора, лицензию и совместимость с API 1, приложите инструкции владельцу.

Для разработки API и ограничений полезны [CodeFrame](../shared/CodeFrame.vue), [runtime iframe](../apps/api/src/codeFrame.js), [схема пакетов](../shared/themes.js) и [SECURITY](../SECURITY.md). Изоляция не делает неизвестную тему доверенной: её внешний CSS и публичное содержимое всё равно могут вводить покупателя в заблуждение. Устанавливайте проверенные пакеты и сохраняйте рабочую версию перед публикацией.
