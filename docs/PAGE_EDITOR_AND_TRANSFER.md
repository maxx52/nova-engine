# Редактор страниц и перенос данных

NOVA Engine 0.25.0.

## Блоки страницы

В разделе «Страницы» создайте страницу или откройте существующую. Секции можно перетаскивать за ручку ⋮⋮ мышью или пальцем на сенсорном экране. Кнопки ↑/↓ остаются доступны для клавиатуры и перемещения за пределы видимой области. Максимум — 50 блоков на страницу.

У каждого блока есть поле «Название в библиотеке» и кнопка «Сохранить секцию». Сохранение в библиотеку не сохраняет страницу и не публикует её. Библиотека общая для сайта, доступна владельцу, администратору и редактору; лимит — 200 секций. Вставка создаёт отдельную копию с новым ID. Изменение или удаление сохранённого блока не меняет уже вставленные копии. Блоки с формами и изображениями сохраняют ссылки на существующие данные, а не отдельные копии форм и файлов.

Секции в библиотеке учитываются при проверке использования изображений в медиатеке. Для переноса между установками используйте экспорт страниц: библиотека секций в выгрузку контента пока не включена.

## Мобильный предпросмотр

Кнопка «Мобильный предпросмотр» показывает текущий несохранённый заголовок, вступительный текст и блоки в отдельном iframe. Доступны реальные ширины viewport: 390, 768 и 1280 px. Смена ширины проверяет переносы и адаптивные CSS-правила, а не просто уменьшает картинку.

Предпросмотр использует опубликованные цвета и шрифт сайта и тот же компонент секций, что и публичная страница. Шапка, подвал, глобальный пользовательский CSS и шаблон страницы активной темы не включены: окончательный результат проверьте на сайте после сохранения. Формы заменены заглушками, переходы по ссылкам отключены. HTML/CSS/JavaScript не выполняется до включения флажка «Выполнить код секций в изоляции». Код работает в отдельной песочнице без доступа к DOM админки и административным действиям. Изменение полей обновляет предпросмотр без публикации.

В режиме разработки используйте обычный `npm run dev:all`: iframe загружает модуль предпросмотра через Vite. В production документ предпросмотра входит в сборку админки и отдаётся API только после проверки сессии. Контейнер API также содержит этот документ; ассеты обслуживает веб-сервер из `/admin/assets/`.

## Экспорт

Раздел «Импорт и экспорт» доступен владельцу и администратору. Выберите тип и нажмите «Экспорт JSON». Поддерживаются товары, покупатели, страницы и статьи блога. Экспорт разбивается на части по размеру и числу записей: не более 4 МБ и 500 записей в части; для объёмного контента частей будет больше. Если показана кнопка «Скачать следующую часть», сохраните и её, пока выгрузка не закончится. На время большой выгрузки желательно не менять состав записей: части читаются последовательно по смещению.

В выгрузку попадают редактируемые данные: варианты и остатки товаров, SEO, секции страниц, теги статей, контакты и заметки покупателей. Системные ID, пользователи админки, пароли, ключи, заказы, история операций, платёжные данные и настройки сервисов не экспортируются. JSON содержит обычный текст: формулы из названий не выполняются. Выгрузка не является полной резервной копией; полное восстановление доступно через «Обновления и копии».

Изображения не упаковываются в JSON. Перенесите файлы отдельно с сохранением путей `/uploads/<uuid>.<расширение>` и учётом медиатеки. При старте API выполняет синхронизацию каталога uploads. Формы перенесите/создайте отдельно и замените `form_id` в секциях. Импорт заранее проверяет, что все ссылки существуют на целевом сайте; интернет-адреса не скачиваются сервером.

## Импорт и предварительная проверка

1. Выберите тип данных и режим: только добавление либо добавление и обновление совпадений.
2. Загрузите JSON NOVA или CSV для товаров/покупателей. Кнопки «Пример JSON» и «Пример CSV» дают точную структуру. Лимит — 4 МБ и 500 записей в одном файле.
3. Нажмите «Проверить файл». База товаров, покупателей и контента в этот момент не меняется. Показываются ошибки по строкам, действия «Создать», «Обновить», «Без изменений», предупреждения и изменяемые поля. Длинные значения в сравнении сокращаются до 300 символов; полный текст проверьте в исходном файле.
4. Исправьте все ошибки. Даже одна ошибочная строка запрещает применение всего файла. Исправленный файл загрузите и проверьте заново.
5. Просмотрите предупреждения, установите флажок подтверждения и нажмите «Применить проверенный импорт».

Сопоставление:

| Данные | Ключ |
| --- | --- |
| Товар | Артикул `sku`, с удалением пробелов по краям, с учётом регистра |
| Покупатель | Нормализованный телефон `phone` |
| Страница | Адрес `slug` |
| Статья | Адрес `slug` |

Пустой артикул разрешён только как создание нового товара без сопоставления. Каждый новый импорт такой строки снова создаст товар; для повторных выгрузок назначьте уникальные артикулы. Повторы ключей в файле или несколько товаров с одним артикулом на сайте считаются ошибкой. В режиме «Только добавлять» любое существующее совпадение тоже считается ошибкой.

В режиме обновления отсутствующие поля сохраняют текущие значения. Переданное пустое значение означает очистку поля, а переданный массив — полную замену массива. Особенно внимательно проверяйте остатки и варианты. У нового товара, страницы или статьи `published` по умолчанию `false`; публикация из файла возможна только при явно переданном `true` и сопровождается предупреждением.

Проверка действует 30 минут и привязана к учётной записи, выполнившей её. Смена файла или режима требует новой проверки. При применении сервер блокирует конкурентные изменения целевого типа данных, сверяет версии/содержимое и повторно проверяет ссылки на медиа и формы. Если после проверки оформлен заказ и изменился остаток, запись была отредактирована/удалена или появился совпадающий ключ, импорт остановится без частичных изменений. Проверьте исходные данные и повторите предварительную проверку.

Весь файл применяется в одной транзакции. Повторный запрос применения того же проверенного файла возвращает уже полученный результат и не создаёт повторные записи. Импорт не удаляет существующие записи, не меняет снимки контактов и товаров в старых заказах и не отправляет уведомления. Новые категории товаров создаются по названиям без переноса дерева категорий. Черновик проверенного импорта удаляется по истечении срока; после успешного применения его содержимое очищается, остаётся краткий результат.

### JSON

```json
{
  "format": "nova-data",
  "version": 1,
  "kind": "products",
  "records": [
    {"name":"Товар","category":"Другое","price":100.5,"sku":"IMPORT-001","stock":5,"published":false}
  ]
}
```

Вместо `products` поддерживаются `customers`, `pages`, `posts`. ID и неизвестные поля не принимаются. Выгрузку NOVA можно использовать без изменения формата; дополнительные поля оболочки `next_offset` игнорируются при чтении файла.

### CSV

UTF-8, допускается BOM. Первая строка — английские имена полей. Разделитель — запятая или точка с запятой; кавычки, двойные кавычки внутри поля и многострочные поля поддерживаются. Цена — рубли, максимум две цифры после десятичного разделителя. Для запятой в дробной части удобнее разделитель `;`. `stock` — целое число, `published` — `true/false` или `1/0`. Поля `images`, `attributes`, `variants`, `seo`, если включены, содержат JSON в CSV-ячейке.

Для товаров обязательны `name`, `category`, `price` при создании; для покупателей — `name`, `phone`. При обновлении нужен ключ и изменяемые поля. Секции страниц и полный контент переносите через JSON.
