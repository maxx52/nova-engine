# Согласование и отложенная публикация

NOVA Engine 0.27.0 добавляет согласование и расписание для **страниц и статей**. Очередь находится внизу соответствующего раздела админки. Товары, оформление и темы работают по прежним правилам.

## Права

| Роль | Возможности |
| --- | --- |
| Владелец и администратор | Публикация напрямую, проверка всех заявок, возврат с комментарием, одобрение сразу или на выбранное время, отмена ожидающих заявок |
| Редактор | Создание и сохранение неопубликованных материалов, личные черновики опубликованного текста, отправка на согласование, просмотр своих заявок и комментариев, отмена своих ожидающих заявок |
| Менеджер | Нет доступа к страницам, статьям и очереди |

**Изменение относительно 0.26.0:** редактор больше не публикует страницы и статьи напрямую. Поле «Опубликована» ему недоступно. Его изменения уже опубликованного материала сохраняются отдельным личным черновиком: кнопка называется **Сохранить личный черновик**. Публичный текст при этом остаётся прежним. Правила корзины и удаления по ролям сохраняются.

## Отправить текст на проверку

1. Откройте материал. Новый материал сначала сохраните неопубликованным и откройте снова.
2. Внесите изменения, при необходимости восстановите личный черновик.
3. В блоке **Согласование и публикация по расписанию** выберите **Отправить на согласование**. Можно указать желаемое время; окончательное решение принимает администратор.
4. Заявка получает отдельную копию текущего текста, секций, SEO и других редактируемых полей. Это не публикация. Личная рабочая копия остаётся доступной для восстановления.

Одновременно у одного материала может быть только одна ожидающая заявка: на согласовании или в расписании. Для другой версии отмените прежнюю заявку. Повтор сетевого запроса с тем же идентификатором и теми же данными не создаёт дубль.

## Проверить и одобрить

В очереди нажмите **Проверить заявку**. Сравнение показывает текущие поля материала и отправленную копию. HTML и JavaScript выводятся текстом, без исполнения.

- **Вернуть с комментарием** требует непустого комментария. Автор увидит его в своей очереди; опубликованный материал не меняется. Он может восстановить личный черновик, исправить текст и отправить новую заявку.
- **Одобрить и опубликовать** сразу применяет именно отправленную копию, создавая новую версию в истории.
- Если выбрать дату, кнопка изменится на **Одобрить и запланировать**. До наступления времени публичный материал остаётся прежним.
- **Отменить заявку** работает для ожидающих заявок. Уже опубликованное решение не отменяется этой кнопкой: воспользуйтесь редактором и историей версий.

В очереди по умолчанию видны и завершённые решения. Флажок **Показывать завершённые заявки** позволяет оставить только ожидающие. Очередь обновляется каждые 30 секунд, также есть ручное обновление и переход между частями по 20 заявок.

## Назначить публикацию без согласования

Владелец или администратор открывает материал, вносит изменения, раскрывает блок расписания, указывает дату и нажимает **Запланировать публикацию**. Отправляется текст редактора, включая ещё не применённые изменения. До срока они не изменяют ни публичный текст, ни сохранённую версию материала.

Часовой пояс указан рядом с полем времени и берётся из браузера. Сервер хранит момент в UTC. Допустимый срок — от 5 секунд до 366 дней вперёд. При переходах часового пояса проверьте время в очереди после создания заявки. Для статей модуль блога должен быть включён, чтобы опубликованные статьи были доступны посетителям.

Служба API проверяет расписание каждые 15 секунд, по 10 заявок за проход. Публикация происходит в ближайший проход после указанного времени, с возможной задержкой при большой очереди. Сервер должен иметь верное системное время. При остановленном API публикация задержится до его запуска; очередь сохраняется в PostgreSQL, просроченные задания обрабатываются после перезапуска. Несколько экземпляров API используют блокировки и не публикуют один снимок дважды.

## Изменения, ошибки и история

Заявка привязана к номеру исходной версии. Если материал сохранить, изменить импортом, переместить в корзину или восстановить, ожидающая заявка станет **Устарело**. Даже если текст затем вернули к прежнему виду, старое одобрение не применяется. Личный автосохранённый черновик не меняет версию материала и не отменяет заявку.

Перед применением сервер проверяет версию, наличие материала вне корзины, изображения, формы и действующие права одобрившего пользователя. Отключённая учётная запись или отозванная роль одобрившего пользователя блокирует отложенную публикацию. Недоступная форма или занятый адрес оставит прежний текст без частичного сохранения; очередь покажет ошибку. После исправления отправьте новую заявку. Автоматических повторов заявки, перешедшей в состояние ошибки, нет.

Активные заявки защищают свои изображения от удаления из медиатеки. Завершённая заявка сама по себе не удерживает изображения; их могут продолжать удерживать материал, история или личные черновики. При создании следующей заявки сохраняются последние 30 завершённых решений для этого материала. Окончательное удаление материала удаляет его заявки. Полный бэкап базы включает очередь, комментарии и снимки.

В истории версий успешное применение отмечается как **Публикация** с автором одобрения. Переходы заявок фиксируются в существующем журнале действий без текста содержимого. Письма и сообщения в Telegram этот этап не отправляет.

## API

База маршрутов — `/api/admin/pages` или `/api/admin/posts`. Нужны сессия, права роли и CSRF для изменений.

| Запрос | Назначение |
| --- | --- |
| `GET /publications?state=all&offset=0` | Очередь, до 20 элементов и `next_offset`; редактор видит только свои заявки |
| `GET /publications?state=active&record_id=123` | Ожидающие заявки конкретного материала |
| `GET /publications/:request_id` | Снимок заявки, решение и текущий материал для сравнения |
| `POST /:id/publications` | `{request_id, revision, payload, mode, publish_at}`; UUID v4, строковая версия исходного материала, только редактируемые поля; `mode` — `review` либо `schedule` |
| `POST /publications/:request_id/approve` | `{revision, note, publish_at}`; строковая версия заявки; `publish_at: null` — сейчас, иначе дата UTC ISO |
| `POST /publications/:request_id/reject` | `{revision, note}` с обязательным комментарием до 2000 символов |
| `POST /publications/:request_id/cancel` | `{revision}`; автор или администратор |

Для создания `publish_at` — ISO UTC либо `null`. Для `schedule` дата обязательна. `payload` не содержит ID, служебные даты, версии или пользователей; он проверяется как полноценный материал, а `published` при применении становится `true`. Номер версии материала и номер версии заявки — разные значения. Устаревшие действия возвращают HTTP 409, чужая заявка редактору — HTTP 404.
