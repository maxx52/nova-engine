# SEO в NOVA Engine 0.23

## Настройка через админку

Владелец и администратор открывают **SEO и редиректы**. Здесь задаются основной HTTPS-адрес сайта, описание по умолчанию, разрешение индексации, дополнительные запрещённые пути robots.txt и SEO главной страницы, каталога и списка статей. Изменения защищены номером ревизии: сохранение устаревшей формы возвращает конфликт вместо перезаписи новых настроек.

Основной адрес — origin без пути и завершающего слеша: `https://example.ru`. Он используется для canonical, Open Graph, sitemap и микроразметки. Если поле пустое, используется доверенная переменная сервера `PUBLIC_SITE_URL`, а при её отсутствии — первый `ADMIN_ORIGINS` в production. Если админка и сайт имеют разные домены, укажите адрес именно публичной витрины. Заголовки Host и X-Forwarded-Host не определяют канонический домен.

В редакторах **страницы, товара и статьи** раскройте **SEO и предпросмотр ссылки**:

- SEO-заголовок, до 200 символов; по умолчанию название материала и сайта.
- Метаописание, до 500 символов; по умолчанию краткий текст материала или описание сайта.
- Канонический внутренний путь, например `/about`. Обычно его нужно оставить пустым: правильный адрес определяется автоматически. Внешние домены, query-параметры и служебные пути не допускаются.
- Изображение Open Graph из медиатеки. Для товара по умолчанию берётся его фотография, для статьи — обложка.
- noindex и nofollow.

SEO-поля сохраняются вместе с материалом. Редактор может менять SEO доступного ему контента; глобальные настройки и редиректы доступны владельцу и администратору. Изображения, используемые только в SEO, тоже учитываются медиатекой и защищены от удаления.

Выдаётся title, description, robots, canonical, Open Graph и Twitter Card. При переходах по витрине обновляются title, метатеги, canonical и JSON-LD; разметка предыдущего товара удаляется. При прямом открытии адреса метатеги доступны уже в исходном HTML, если включена маршрутизация, описанная ниже. Это серверная HTML-оболочка с метаданными и текстовым содержимым, а не полная SSR-версия всех компонентов тем.

## sitemap.xml и robots.txt

`/sitemap.xml` — индекс карт. `/sitemap-1.xml`, `/sitemap-2.xml` и далее содержат до 1000 адресов каждая. Карты строятся из базы, без пересборки после изменения контента. В них входят главная, включённые каталог и блог, опубликованные страницы, товары и статьи. Исключаются noindex, альтернативные canonical, страницы отключённых модулей, источники редиректов и пути, запрещённые дополнительными правилами. Страница, выбранная главной, не дублируется в карте своим slug; её canonical по умолчанию — `/`.

`lastmod` берётся из даты изменения материала; для технических страниц без достоверной даты не придумывается. Пустые и несуществующие части карты возвращают 404. Карта не содержит админку, API, черновики, заказы и данные покупателей.

`/robots.txt` автоматически содержит ссылку на sitemap и ограничения `/admin/`, `/api/`. Дополнительные запрещённые пути задаются по одному на строку и работают как префиксы. При отключении индексации выводится `Disallow: /`, страницы получают noindex, карта становится пустой. Для тестового `nova.maxxdev.ru` владелец может отключить индексацию, оставив её включённой на рабочем домене. Robots и noindex не заменяют авторизацию и не гарантируют немедленное удаление уже известных поисковику страниц.

## Редиректы

Укажите старый и новый внутренний адрес и код 301/302/307/308. Совпадение точное по нормализованному пути; завершающий слеш не различается. Параметры запроса не переносятся. Внешние адреса, обратные слеши, управляющие символы, неоднозначное кодирование и служебные пути запрещены.

Нельзя добавить дубль исходного адреса или правило, создающее цикл; проверка выполняется в транзакции, включая одновременные изменения. Лимит — 10 000 правил. Для изменения правила удалите прежнее и добавьте новое. После смены slug страницы или статьи создайте редирект со старого адреса самостоятельно: он не создаётся автоматически.

Редирект применяется до поиска материала и может перекрыть существующую публичную страницу. Используйте 301/308 только для окончательного переноса: браузеры и поисковики могут их кешировать. JSON API метаданных также сообщает редирект для клиентских переходов, но правильный HTTP-статус требует подключения веб-сервера к NOVA API.

## Микроразметка

JSON-LD Schema.org строится автоматически: WebSite и Organization на главной, WebPage для страниц, Product с Offer для товаров, BlogPosting для статей и BreadcrumbList для вложенных материалов. Варианты товара представлены действительными предложениями с собственными ценами, SKU и наличием; атрибуты вариантов и оценки не выдумываются. Валюта RUB соответствует текущему магазину. Параметры доставки, возврата и отзывы в этой версии не моделируются.

Разметка не гарантирует расширенный результат поиска. После настройки проверьте несколько адресов в Google Rich Results Test и инструментах Яндекс Вебмастера. Основные источники: [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [Schema.org Product](https://schema.org/Product), [протокол Sitemap](https://www.sitemaps.org/protocol.html).

## Подключение на хостинге

### Новая Docker-установка

Актуальный `deploy/docker/Caddyfile` уже передаёт публичные HTML-адреса, robots.txt и карты в API. JS/CSS/assets и админка обслуживаются статически. Образ API содержит сборку витрины для формирования HTML. Достаточно собрать и запустить актуальные образы обычным способом. При обновлении существующей Docker-установки пересоберите и API, и web.

### Существующий nginx / aaPanel / VDS

Обновление приложения **не изменяет конфигурацию работающего nginx**. Один раз подключите новую маршрутизацию только в виртуальном хосте сайта NOVA. Сохраните действующую конфигурацию; оставьте сертификаты, правила ACME, обслуживание, `/api/`, `/uploads/` и `/admin/`. Полный пример: [nginx.single-domain.conf.example](../deploy/nginx.single-domain.conf.example).

Для текущей native-схемы NOVA на VDS API работает на `127.0.0.1:3101`. Замените существующий `location /` и добавьте явное статическое обслуживание assets, если такого блока ещё нет:

```nginx
location ^~ /assets/ {
    try_files $uri =404;
}
location = /favicon.ico {
    try_files $uri =404;
}
location / {
    # Этот локальный заголовок отменяет наследование add_header на обычном
    # nginx: полный набор защитных заголовков и CSP приходит от NOVA API.
    add_header X-Nova-SEO server always;
    proxy_pass http://127.0.0.1:3101;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 5s;
    proxy_read_timeout 20s;
}
```

Не добавляйте второй `location /`, не меняйте другой сайт `maxxdev.ru`. При иной установке используйте свой порт API и публичный root. Проверьте конфигурацию `nginx -t`, затем выполните reload службы nginx способом, принятым в вашей панели. У aaPanel может быть свой путь к бинарнику nginx.

API читает HTML из `apps/storefront/dist/index.html`; сначала соберите витрину (`npm run build -w @nova/storefront`). Статические assets веб-сервера должны соответствовать этой же сборке. Запрос без сборки получает 503. Если хостинг позволяет проксировать только `/api`, клиентские метатеги работают, но исходный HTML, корневые карты, HTTP-редиректы и корректные статусы публичных страниц потребуют помощи администратора хостинга.

Проверка после подключения: исходный HTML `/product/1` содержит индивидуальный title, canonical и JSON-LD; `/robots.txt` отдаёт текст, `/sitemap.xml` — XML, отсутствующий slug возвращает HTTP 404, добавленный редирект — выбранный HTTP-код с Location. Не считайте подключение завершённым только по появлению SEO-полей в админке.
