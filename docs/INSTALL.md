# Установка NOVA одной командой

Для управляемого Node.js-хостинга и VDS с уже установленной панелью используйте [отдельную инструкцию](HOSTING.md). Перед выбором тарифа проверьте [системные требования](REQUIREMENTS.md).

Установщик **installer-v1.0.0** предназначен для **нового выделенного VDS** с Ubuntu 22.04/24.04 или Debian 12/13. Он устанавливает Docker из официального apt-репозитория (если Docker отсутствует), собирает CMS и запускает PostgreSQL, API, витрину и админку. Caddy получает и обновляет HTTPS-сертификат. Данные сохраняются в Docker volumes.

## Подготовка

- VDS: root/sudo, от 2 ГБ RAM и 4 ГБ свободного диска; для рабочего магазина выбирайте запас ресурсов под данные и резервные копии.
- Домен: A-запись указывает на IPv4 VDS. Если есть AAAA, она должна указывать на работающий IPv6 этого же VDS. Изменение DNS выполняется у регистратора заранее, установщик его не меняет.
- Входящие TCP 80 и 443 доступны из интернета; исходящие HTTPS и DNS доступны серверу. Docker публикует эти два порта; не полагайтесь только на UFW для фильтрации опубликованных Docker-портов.
- Нужны `curl`, `tar`, `python3`, `ss` (iproute2), `openssl`, стандартные GNU-утилиты. Обычно они уже есть в образе Ubuntu. При необходимости: `sudo apt-get update && sudo apt-get install -y curl ca-certificates tar python3 iproute2 openssl`.
- Порты 80/443 должны быть свободны. Установщик не останавливает nginx, Apache, aaPanel и другие сайты, не меняет их конфигурацию. Наш действующий `nova.maxxdev.ru` уже установлен отдельно: запускать на нём этот установщик не нужно.

## Одна строка в терминале

Замените `shop.example.ru` своим доменом:

```bash
curl -fsSL https://raw.githubusercontent.com/maxx52/nova-engine/installer-v1.0.0/scripts/install.sh -o /tmp/nova-install.sh && sudo bash /tmp/nova-install.sh --domain shop.example.ru
```

Команда выполняет установщик с правами root. Перед запуском можно просмотреть скачанный `install.sh`; источник — наш репозиторий GitHub, версия вынесена в отдельную ветку релиза. Установщик загружает код из этой же ветки релиза, а не из `main`. При существующем `/opt/nova`, проекте Docker `nova`, занятых портах или несовместимых пакетах Docker установка остановится с объяснением. Старые данные не удаляются.

Сборка занимает несколько минут. Для Docker Hub, npm, GitHub и центра сертификации нужен сетевой доступ. Если провайдер блокирует эти сервисы, установка завершится ошибкой: установщик не отключает проверку TLS.

После сообщения `NOVA is ready`:

1. Откройте `https://ваш-домен/admin/`.
2. В терминале сервера выполните `sudo cat /opt/nova/setup-key`. Введите этот ключ в форму первоначальной настройки.
3. Задайте свой логин и пароль администратора. Общего пароля по умолчанию нет. Не отправляйте ключ или `.env` в чат, GitHub и службу поддержки.

Это **автоматическая установка инфраструктуры плюс создание учётной записи в браузере**. Установка «одним кликом» в каталоге хостера потребует отдельной интеграции с этим хостером.

## Что устанавливается

Код и настройки: `/opt/nova`, каталог доступен только root. Файл `.env` и `setup-key` имеют права `600`. PostgreSQL получает отдельный пароль владельца и отдельного пользователя `nova_app` без прав суперпользователя; API использует только `nova_app`. База и API не публикуют порты на хост. API работает от пользователя `node`; доступ через один HTTPS-домен, админка по `/admin/`.

Docker volumes проекта `nova`: `nova_database`, `nova_uploads`, `nova_certificates`, `nova_caddy_config`. Сеть приложения: `172.30.92.0/24`, доверенный reverse proxy: `172.30.92.2`. Если эта подсеть пересекается с сетью вашего сервера/VPN, этот вариант требует ручной настройки **до запуска**. Установка не меняет правила вашего firewall. SMTP и Telegram подключаются позднее в админке.

Код тем и платёжных виджетов сохраняет собственные CSP/sandbox-заголовки API. Прокси не подменяет их заголовками обычных HTML-страниц.

## Состояние, остановка и восстановление установки

```bash
cd /opt/nova
sudo docker compose --env-file .env -f deploy/docker/compose.yaml ps
sudo docker compose --env-file .env -f deploy/docker/compose.yaml logs --tail=100 api web
```

Если установка прервалась **после создания `/opt/nova/.nova-install`**, устраните причину (сеть, DNS, нехватка ресурсов), затем:

```bash
sudo bash /tmp/nova-install.sh --resume
```

Возобновление использует уже скачанный код и прежние секреты, не создаёт новые пароли и не очищает базу. При сбое до создания `.nova-install` сначала выясните причину; не удаляйте каталоги или volumes, если там могут быть нужные данные. Установка Docker могла успеть завершиться, даже если дальнейший шаг упал.

Остановить контейнеры с сохранением данных:

```bash
cd /opt/nova
sudo docker compose --env-file .env -f deploy/docker/compose.yaml stop
```

Не используйте `down -v`: эта команда удаляет данные. Переустановка и обновление существующей CMS не входят в этот установщик. Перед обновлением нужны резервная копия, проверка миграций и возможность отката. Теги Docker фиксируют основные версии компонентов; для воспроизводимого корпоративного развёртывания закрепите проверенные образы по digest.

## Резервная копия

Установка не заменяет настройку регулярных резервных копий. Сделайте первую копию после настройки, затем автоматизируйте её и храните копии вне VDS. Например, от root, в момент отсутствия редактирования и загрузки файлов:

```bash
sudo -i
cd /opt/nova
umask 077
backup_dir="/var/backups/nova/$(date -u +%Y%m%dT%H%M%SZ)"
mkdir -p "$backup_dir"
docker compose --env-file .env -f deploy/docker/compose.yaml stop api
docker compose --env-file .env -f deploy/docker/compose.yaml exec -T db pg_dump -U postgres -d nova -Fc > "$backup_dir/database.dump"
docker compose --env-file .env -f deploy/docker/compose.yaml cp api:/var/lib/nova/uploads "$backup_dir/uploads"
cp .env .nova-install "$backup_dir/"
docker compose --env-file .env -f deploy/docker/compose.yaml start api
```

Если команда копирования упала, запустите API вручную последней командой. Восстановление проверяйте на отдельном сервере: база, uploads, прежний `.env` (он нужен для расшифровки настроек интеграций) и та же версия исходников должны соответствовать друг другу. Копии содержат секреты и данные покупателей.

## 1Gb.ru и установка из панели

Эта команда предназначена для Linux VDS/VPS с root и Docker. Она не является PHP-установщиком для обычного виртуального хостинга. Для размещения у 1Gb.ru нужно отдельно проверить возможности конкретного тарифа: Docker/root либо постоянный Node.js-процесс, PostgreSQL и reverse proxy. Наличие домена у 1Gb.ru не мешает установке на отдельный VDS: DNS направляется на этот VDS.

Источники для инфраструктуры: [официальная установка Docker](https://docs.docker.com/engine/install/ubuntu/), [автоматический HTTPS Caddy](https://caddyserver.com/docs/automatic-https), [образ PostgreSQL и init-скрипты](https://hub.docker.com/_/postgres).
