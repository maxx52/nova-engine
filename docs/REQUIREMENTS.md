# Системные требования NOVA CMS

Для NOVA Engine 0.20 и установщика `installer-v1.0.0`. Проверено по коду проекта и документации провайдера 18 октября 2026 года.

## Программное окружение

| Компонент | Требование |
| --- | --- |
| Сервер приложений | Постоянно работающий Node.js 22.12+; Docker-образ проекта использует Node.js 24 |
| База данных | PostgreSQL 17 — версия, используемая и проверяемая проектом; MySQL и SQLite не заменяют её |
| Роль базы | Отдельная LOGIN-роль, владеющая базой/схемой приложения и имеющая права создавать и изменять таблицы, индексы и последовательности; без SUPERUSER, CREATEDB, CREATEROLE, REPLICATION, BYPASSRLS и привилегированных наследуемых ролей |
| Зависимости | npm и установка по `package-lock.json`; разрешена установка нативного модуля обработки изображений `sharp` для целевой ОС/архитектуры |
| Веб-сервер | HTTPS, раздача статических файлов и reverse proxy к Node.js; отдельные правила для API, uploads, code-frame и payment-frame |
| Процессы | Один экземпляр API, автозапуск и перезапуск после сбоя; фоновые очереди форм требуют постоянного процесса |
| Файлы | Постоянный записываемый каталог uploads вне публичной папки и сохранение его между перезапусками/релизами |
| Управление | SSH/SFTP или эквивалентная панель, установка зависимостей, переменные окружения, доступ к журналам и управлению процессом |
| Браузер | Современный браузер с JavaScript, cookies и iframe; HTTPS для защищённых сессий администратора |

Фактический минимум Node.js задан в `package.json`. Другие версии PostgreSQL отдельно не сертифицированы этой инструкцией. Публиковать порты базы и API непосредственно в интернет не требуется.

**Недостаточно:** только PHP, FTP, MySQL, статический хостинг или возможность один раз запустить `node` по SSH. Запуск `npm run dev:all` не является production-развёртыванием.

## Ресурсы

Ниже стартовые инженерные ориентиры для небольшого сайта, а не результаты нагрузочного теста или обещание определённого числа посетителей.

| Сценарий | CPU | RAM | Диск |
| --- | --- | --- | --- |
| Node.js-хостинг, внешняя PostgreSQL, сборка на другой машине | Эквивалент от 1 vCPU / достаточная квота CPU | От 1 ГБ доступной памяти приложению | От 1 ГБ для кода и production-зависимостей, отдельно место для uploads |
| Новый VDS: приложение, база и сборка на одном сервере | От 1 vCPU, удобнее 2 | От 2 ГБ | Установщик проверяет 4 ГБ свободного места; практический старт — SSD от 20 ГБ для ОС, образов и данных |
| Небольшой рабочий магазин с запасом | От 2 vCPU | Ориентир от 4 ГБ | SSD от 20–40 ГБ и отдельное хранение резервных копий |

Учитывайте изображения, базу, журналы, Docker-кэш и резервные копии. На виртуальном хостинге уточняйте именно лимит памяти и CPU **длительно работающего Node.js-процесса**, а не только место по тарифу. Параллельные загрузки больших изображений повышают расход памяти. При росте нагрузки ресурсы подбираются по измерениям.

## Сеть и доступ

- Домен и HTTPS; точный HTTPS-origin админки в `ADMIN_ORIGINS`.
- Для установки: доступ к GitHub, npm и источнику сборок Node.js; для Docker-варианта также к Docker Hub и официальному репозиторию Docker.
- Доступ API к PostgreSQL. При соединении через публичную сеть — TLS с проверкой сертификата; самоподписанный сертификат требует доверенного CA, а не отключения проверки.
- Для Telegram: исходящий HTTPS к `api.telegram.org`; для SMTP — разрешённый исходящий порт выбранного почтового сервера. Режим почты выбирается в админке.
- Reverse proxy сохраняет Host, заменяет клиентские forwarding-заголовки доверенными значениями; `TRUST_PROXY` содержит только адреса реального прокси, а не `true` или все сети.
- Прокси/CDN не кэширует `/api/` и не удаляет `Set-Cookie`. Заголовки CSP/sandbox для `/api/code-frame` и `/api/payment-frame` сохраняются отдельно от заголовков обычных HTML-страниц. Нужны POST/PUT/DELETE API, не только GET.
- Лимит HTTP-запроса от 6 МБ, чтобы проходила загрузка изображения до 5 МБ с multipart-обрамлением.

## Что спросить у хостера до покупки тарифа

1. Можно ли постоянно запускать Node.js 22.12+ или 24 и автоматически перезапускать процесс? Каков лимит RAM/CPU, есть ли остановка при простое?
2. Доступна ли PostgreSQL 17 и отдельный непривилегированный пользователь с правами миграции собственной схемы?
3. Можно ли установить `sharp`, запускать `npm ci` и хранить uploads постоянно? Поддерживается ли выбранная ОС/архитектура пакетом?
4. Можно ли на одном HTTPS-домене раздавать витрину и `/admin/` как статику, а `/api/` и `/uploads/` направить в Node.js? Можно ли сохранять специальные заголовки iframe и передавать cookies?
5. Какие порт, интерфейс и адрес доверенного прокси нужно указать? Как передаётся HTTPS и исходный IP посетителя?
6. Разрешены ли исходящие SMTP и Telegram? Как получить резервную копию базы и файлов и восстановить их?

Если хотя бы один обязательный пункт недоступен, данный тариф пока нельзя считать совместимым. [Инструкция по размещению](HOSTING.md) · [Автоустановка на новый VDS](INSTALL.md).
