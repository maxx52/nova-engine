# Сохранение страниц и статей

Доступно с NOVA Engine 0.26.0 в разделах **Страницы** и **Блог**. Товары и покупатели используют прежние редакторы; этот выпуск не добавляет им историю и корзину.

## Личный черновик

Через 1,2 секунды после изменения редактор сохраняет вашу рабочую копию на сервере. Это отдельные данные вашей учётной записи: сайт продолжает показывать последнюю сохранённую публикацию. Можно оставить незаполненный заголовок или некорректный адрес и продолжить позже. Статус «Личный черновик сохранён» подтверждает успешную запись. При ошибке сети или завершении сессии статус покажет причину; закрытие несохранённого редактора требует подтверждения.

После перезагрузки откройте материал и выберите **Восстановить личный черновик**. Для ещё не созданного материала нажмите **Создать страницу/статью**: у каждого редактора есть одна новая рабочая копия каждого типа. Можно удалить найденную копию и продолжить с сохранённым содержимым. Восстановление само по себе ничего не публикует. Кнопка **Сохранить** проверяет все обязательные поля и сохраняет материал с выбранным статусом публикации.

Рабочие копии других пользователей недоступны, включая владельца сайта. Не помещайте в содержимое пароли или ключи: резервная копия базы данных содержит и личные черновики. Изображения из рабочих копий защищены от удаления в медиатеке.

## Два редактора или две вкладки

Каждое сохранение увеличивает номер версии. Сервер принимает изменение только относительно той версии, которую вы открыли. Если материал уже сохранён другим редактором или импортом, CMS оставляет ваш текст в редакторе и показывает сравнение с сервером. Можно загрузить серверный вариант или выбрать **Продолжить с моим вариантом**, проверить текст и снова сохранить. При повторном конфликте проверка повторяется. Автоматического объединения текста нет.

Для личного черновика также проверяется версия. Если две вкладки одной учётной записи начали менять один материал, вторая не перезапишет рабочую копию первой. При таком конфликте скопируйте свой текст, закройте редактор и откройте его снова. Если запись уже в корзине, скопируйте нужный текст; восстановите материал из корзины перед продолжением работы.

## История

**История версий** хранит последние 30 сохранённых состояний каждого материала, включая создание, импорт, перенос в корзину и восстановление. Автосохранения в эту историю не входят. При первом обновлении CMS текущие материалы получают начальную версию; более ранних состояний в базе нет.

Выберите версию, сравните изменённые поля и нажмите **Загрузить версию как черновик**. Она появится в редакторе с выключенной публикацией; проверка и кнопка **Сохранить** создадут новую версию. История не откатывает базу целиком и не отменяет изменения других материалов. HTML и JavaScript при сравнении отображаются как текст и не выполняются. Если зависимая форма исчезла, её необходимо заменить перед сохранением.

Изображения, которые используются в сохранённых версиях, нельзя удалить из медиатеки. Старая версия автоматически удаляется из истории после превышения лимита 30. Хранение истории расходует место в базе, особенно для крупных секций с кодом.

## Корзина

**В корзину** скрывает материал с сайта, из публичных API, блога, sitemap и выбора опубликованной главной страницы. Введённые вручную ссылки в меню остаются ссылками: при необходимости измените их в настройках. Адрес материала остаётся занят. Импорт с совпадающим адресом предложит сначала восстановить материал или удалить его окончательно. Обычный экспорт не включает корзину, историю и личные черновики.

Переключитесь в **Корзину** и выберите **Восстановить**. Материал вернётся неопубликованным. Чтобы вывести его на сайт, откройте редактор, проверьте содержимое и включите публикацию. Если материал был назначен главной страницей, прежнее назначение сохраняется до окончательного удаления, но черновик не становится публичным.

**Удалить окончательно** после подтверждения удаляет материал, все его версии и рабочие копии всех редакторов. Это действие доступно только из корзины и проверяет актуальную версию. Автоматической очистки корзины по сроку нет. Для восстановления после окончательного удаления нужна полная резервная копия.

## API и доступ

Владелец, администратор и редактор работают со страницами и статьями; менеджеру эти операции недоступны. Все изменения требуют сессии и CSRF. Журнал действий фиксирует операции без текста содержимого. История содержит ID автора, когда изменение выполнено через API или импорт; для старых данных и прямых SQL-изменений автор может отсутствовать.

Базовые пути: `/api/admin/pages` и `/api/admin/posts`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /:id` | Актуальный материал вне корзины |
| `PUT /:id` | Сохранение с обязательным строковым `revision` |
| `GET ?trash=1` | Корзина |
| `DELETE /:id` | Перенос в корзину, JSON `{ "revision": "…" }` |
| `POST /:id/restore` | Восстановление черновиком с `revision` |
| `DELETE /:id/purge` | Окончательное удаление из корзины с `revision` |
| `GET /:id/versions` | Метаданные последних версий |
| `GET /:id/versions/:revision` | Поля для восстановления с `published: false` |
| `GET /drafts/:key` | Свой черновик либо `null`; ключ `new` или ID материала |
| `PUT /drafts/:key` | `{ revision, base_revision, payload }`; новая копия имеет `revision: "0"`, `base_revision: null` для `new`, иначе номер исходной версии |
| `DELETE /drafts/:key` | Удаление своей копии с её `revision` |

Конфликт записи возвращает HTTP 409 с `code: "content_conflict"` и текущим материалом. Конфликт рабочей копии возвращает `code: "draft_conflict"` без чужого содержимого. Старые API-клиенты, сохраняющие без номера версии, необходимо обновить. При обновлении базы существующие данные сохраняются; миграция повторяемая.
